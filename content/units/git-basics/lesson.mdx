## Git 是什麼

你一定看過這樣的檔名：`報告_最終版.docx`、`報告_最終版2.docx`、`報告_真的最終版.docx`。**Git** 是一套版本控制系統，幫你記錄檔案每一次的修改：誰改的、什麼時候改的、改了什麼，而且隨時可以回到任何一個版本。

雲端工程師每天都在用 Git。不只是應用程式的程式碼，連伺服器和網路的設定也會寫成檔案放進 Git 管理。

用 Git 管理的資料夾稱為**儲存庫**（repository，常簡稱 repo）。

## 三個區域

Git 把你的檔案分成三個區域，這是理解所有指令的關鍵：

| 區域 | 是什麼 |
|---|---|
| 工作目錄 | 你實際看得到、正在編輯的檔案 |
| 暫存區 | 準備放進下一次提交的修改 |
| 儲存庫 | 已經永久記錄下來的歷史 |

修改的流向是：在工作目錄編輯 → 用 `git add` 放進暫存區 → 用 `git commit` 寫進儲存庫。

為什麼要多一個暫存區？因為你可能同時改了五個檔案，但只想把其中相關的三個記成一次修改。暫存區讓你挑選這次要記錄哪些東西。

## 第一次提交

```bash
# 把目前的資料夾變成 Git 儲存庫
git init

# 查看目前的狀態，這是最常用的指令
git status

# 把檔案放進暫存區
git add README.md

# 把目前資料夾裡所有的修改都放進暫存區
git add .

# 提交，並寫下這次修改的說明
git commit -m "Add project README"

# 查看提交歷史
git log

# 每個提交只顯示一行
git log --oneline
```

每一次提交（commit）都是專案在那個時間點的完整快照，並有一個獨一無二的識別碼。

<Callout title="提交訊息要寫給未來的人看">
`"update"` 或 `"fix"` 這種訊息，三個月後連你自己都看不懂。好的訊息會說明這次修改做了什麼，例如 `"Fix login timeout on slow networks"`。
</Callout>

`git status` 會告訴你每個檔案目前在哪個狀態：

- **Untracked files**：Git 還沒開始追蹤的新檔案。
- **Changes not staged for commit**：已追蹤的檔案被修改了，但還沒放進暫存區。
- **Changes to be committed**：已經在暫存區，下一次提交會包含它。

## 分支

**分支**（branch）讓你從目前的進度岔出一條獨立的線來工作，不影響主線。主線通常叫 `main`。

典型的做法是：要開發新功能或修正問題時，先開一個分支，在上面提交，確認沒問題後再合併回 `main`。這樣 `main` 永遠保持在可以運作的狀態。

```bash
# 列出所有分支，目前所在的分支前面有 * 號
git branch

# 建立新分支並切換過去
git switch -c feature

# 切換到已經存在的分支
git switch main
```

<Callout title="你也會看到 git checkout">
舊的教學用 `git checkout -b feature` 建立分支、用 `git checkout main` 切換分支。效果和 `git switch` 一樣，`switch` 是後來新增的指令，用途比較單純、不容易用錯。
</Callout>

切換分支時，工作目錄裡的檔案會跟著變成那個分支的內容。在 `feature` 分支上新增的檔案，切回 `main` 之後就看不到，因為 `main` 還沒有那些修改。

## 合併

把另一個分支的修改帶進目前的分支，稱為**合併**（merge）。要把 `feature` 合併進 `main`，先切換到 `main`，再執行合併：

```bash
git switch main
git merge feature
```

合併有兩種常見的結果：

- **Fast-forward**：`main` 在你開分支之後沒有新的提交，Git 只要把 `main` 往前移到 `feature` 的位置。
- **合併提交**：兩個分支各自都有新的提交，Git 會建立一個新的提交把兩邊的修改結合起來。

如果兩個分支修改了同一個檔案的同一個地方，Git 無法自己決定要留哪一邊，就會發生**合併衝突**，需要你手動選擇。

## 遠端儲存庫

到目前為止的操作都只發生在你自己的電腦上。要和別人協作，會把儲存庫放到 GitHub 這類平台上，稱為**遠端儲存庫**：

- `git clone`：把遠端儲存庫完整複製一份到本機。
- `git push`：把本機的提交上傳到遠端。
- `git pull`：把遠端的新提交下載並合併到本機。

團隊協作通常搭配 **pull request**：把分支推上去之後，請同事審閱修改，通過後才合併進 `main`。

## 重點整理

- Git 記錄檔案的修改歷史；修改依序經過工作目錄、暫存區、儲存庫。
- `git add` 把修改放進暫存區，`git commit` 把暫存區的內容記錄下來。
- 不確定狀況時先下 `git status`。
- 分支讓你獨立進行一項工作；`git switch -c` 建立並切換分支。
- `git merge` 把另一個分支的修改帶進目前的分支；要先切換到接收修改的那個分支。
- `clone`、`push`、`pull` 用來和遠端儲存庫同步。
