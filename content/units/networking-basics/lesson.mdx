## 為什麼要先學網路

在雲端上，虛擬機、資料庫、儲存服務都是透過網路互相溝通。服務連不上、網站打不開，問題十之八九出在網路設定。這個單元不談硬體，只講之後設定雲端網路時一定會用到的幾個觀念。

## IP 位址

網路上的每一台裝置都需要一個位址，別人才找得到它，這就是 **IP 位址**。最常見的 IPv4 位址由四個 0 到 255 的數字組成：

```bash
192.168.1.10
```

IP 位址分成兩種：

| 類型 | 用途 | 例子 |
|---|---|---|
| 公有 IP | 在網際網路上獨一無二，外面的人連得到 | `203.0.113.25` |
| 私有 IP | 只在內部網路使用，網際網路上連不到 | `10.0.1.5` |

私有 IP 只能使用保留給內部網路的三個範圍：

- `10.0.0.0` 到 `10.255.255.255`
- `172.16.0.0` 到 `172.31.255.255`
- `192.168.0.0` 到 `192.168.255.255`

<Callout title="雲端上的做法">
雲端上的每台虛擬機都有私有 IP，用來和內部的其他機器溝通。只有需要讓外界連進來的機器（例如網站伺服器）才應該配公有 IP，資料庫這類內部服務只留私有 IP 比較安全。
</Callout>

## 子網路與 CIDR

一個網路可以切成比較小的區塊，稱為**子網路**（subnet）。描述一段 IP 範圍的寫法叫 **CIDR**：

```bash
10.0.0.0/16
```

斜線後面的數字表示前面有幾個位元是固定的。IPv4 位址共 32 個位元，所以**數字越大，可用的位址越少**：

| CIDR | 位址數量 | 範圍 |
|---|---|---|
| `10.0.0.0/16` | 65,536 | `10.0.0.0` 到 `10.0.255.255` |
| `10.0.1.0/24` | 256 | `10.0.1.0` 到 `10.0.1.255` |
| `10.0.1.16/28` | 16 | `10.0.1.16` 到 `10.0.1.31` |

位址數量的算法是 2 的（32 減去斜線後的數字）次方。例如 `/24` 是 2 的 8 次方，等於 256。

有兩個特別的寫法會常常看到：

- `0.0.0.0/0`：代表所有 IP 位址，也就是整個網際網路。
- `203.0.113.25/32`：只代表這一個 IP 位址。

在雲端上，你會先建立一個大的網路（例如 `10.0.0.0/16`），再切出幾個子網路分別放不同用途的機器。

## 連接埠

一台機器上可以同時執行很多服務，**連接埠**（port）用來區分資料要交給哪一個。IP 位址像大樓的地址，連接埠像房間號碼。

| 連接埠 | 服務 |
|---|---|
| 22 | SSH，遠端登入 Linux 主機 |
| 80 | HTTP，未加密的網頁 |
| 443 | HTTPS，加密的網頁 |
| 3306 | MySQL 資料庫 |
| 5432 | PostgreSQL 資料庫 |

**防火牆**規則就是用 IP 範圍加連接埠來描述的，例如「允許 `0.0.0.0/0` 連到連接埠 443」代表任何人都可以連到這台機器的 HTTPS 服務。

<Callout title="常見的資安錯誤">
把連接埠 22 或資料庫的連接埠開放給 `0.0.0.0/0`，等於讓全世界都能嘗試登入。管理用的連接埠應該只開放給你自己的 IP 範圍。
</Callout>

## DNS

人記得住 `example.com`，電腦之間溝通用的卻是 IP 位址。**DNS**（Domain Name System）負責把網域名稱轉換成 IP 位址，就像網路的電話簿。

常見的 DNS 紀錄類型：

| 類型 | 作用 | 例子 |
|---|---|---|
| A | 網域名稱對應到 IPv4 位址 | `example.com` → `203.0.113.25` |
| AAAA | 網域名稱對應到 IPv6 位址 | `example.com` → `2001:db8::1` |
| CNAME | 網域名稱對應到另一個網域名稱 | `www.example.com` → `example.com` |

每筆紀錄都有一個 **TTL**（存活時間），表示查詢結果可以被暫存多久。TTL 設得長，查詢比較快，但修改紀錄後要等比較久才會全面生效。

## HTTP 與 HTTPS

瀏覽器和網站之間用 **HTTP** 溝通：瀏覽器送出請求，伺服器回傳回應。**HTTPS** 是加上 TLS 加密的 HTTP，傳輸過程中別人無法偷看或竄改內容。現在的網站都應該使用 HTTPS。

請求會指定一個**方法**，說明想做什麼：

- `GET`：取得資料。
- `POST`：新增資料。
- `PUT`：更新資料。
- `DELETE`：刪除資料。

回應會帶一個**狀態碼**，看第一個數字就知道大致的結果：

| 狀態碼 | 意思 | 常見例子 |
|---|---|---|
| 2xx | 成功 | 200 OK |
| 3xx | 重新導向 | 301 永久搬移 |
| 4xx | 請求端的問題 | 403 沒有權限、404 找不到 |
| 5xx | 伺服器端的問題 | 500 伺服器內部錯誤、503 服務暫時無法使用 |

排查問題時，4xx 通常要檢查請求的網址和權限，5xx 則要去看伺服器本身。

## 延遲與頻寬

這兩個詞常被混為一談，其實是不同的東西：

- **延遲**（latency）：資料從一端到另一端要花多久，通常以毫秒計算。距離越遠延遲越高，所以服務要盡量部署在靠近使用者的地方。
- **頻寬**（bandwidth）：單位時間內最多能傳輸多少資料。

用水管來比喻：延遲是水從一頭流到另一頭的時間，頻寬是水管的粗細。

## 重點整理

- 公有 IP 可以從網際網路連到，私有 IP 只能在內部網路使用。
- CIDR 斜線後的數字越大，範圍越小；`0.0.0.0/0` 代表所有位址。
- 連接埠區分同一台機器上的不同服務；防火牆規則由 IP 範圍和連接埠組成。
- DNS 把網域名稱轉成 IP 位址；A 紀錄對應 IP，CNAME 對應另一個名稱。
- HTTPS 是加密的 HTTP；狀態碼 4xx 是請求端的問題，5xx 是伺服器端的問題。
- 延遲是時間，頻寬是容量。
