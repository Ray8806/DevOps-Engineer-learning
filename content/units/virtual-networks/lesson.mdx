## 什麼是虛擬網路

在自己的機房裡，伺服器接在公司的網路上：有一段自己的 IP 位址、有路由器決定封包往哪裡走、有防火牆擋掉不該進來的連線。

雲端上的**虛擬網路**做的是同一件事，只是全部用軟體設定。你在供應商的資料中心裡劃出一個和別人隔離的網路，自己決定：

- 這個網路用哪一段私有 IP 位址。
- 切成哪些**子網路**，每個子網路放什麼資源。
- 哪些子網路可以直接連到網際網路，哪些不行。
- 允許哪些連線進出。

虛擬機、資料庫、負載平衡器、Kubernetes 叢集，幾乎所有雲端資源都放在某個虛擬網路裡。兩個平台都把這個服務叫做 **VPC**（Virtual Private Cloud）。

## 規劃 IP 範圍

建立網路的第一步是決定用哪一段 IP 位址。一般使用私有位址（RFC 1918）的三段範圍：

| 範圍 | CIDR |
|---|---|
| 10.0.0.0 到 10.255.255.255 | `10.0.0.0/8` |
| 172.16.0.0 到 172.31.255.255 | `172.16.0.0/12` |
| 192.168.0.0 到 192.168.255.255 | `192.168.0.0/16` |

規劃時要注意兩件事：

1. **留夠空間**。網路建好後要換範圍很麻煩，寧可一開始給大一點。
2. **不要和其他網路重疊**。之後如果要把兩個雲端網路接起來，或用 VPN 連回公司，兩邊的範圍重疊就無法互通。每個環境（開發、測試、正式）最好各用不重疊的一段。

<Callout title="複習 CIDR">
`/24` 代表前 24 個位元是網路部分，剩下 8 個位元可以分給主機，也就是 2 的 8 次方 = 256 個位址。斜線後的數字每少 1，位址數量就加倍：`/23` 是 512 個，`/16` 是 65,536 個。
</Callout>

**每個子網路都有幾個位址不能用**，供應商拿來當網路位址、預設閘道等用途。AWS 每個子網路保留 5 個，Google Cloud 保留 4 個。所以一個 `/24` 子網路在 AWS 實際能用的是 251 個。

## 子網路：公有與私有

**子網路**是從網路的範圍再切出來的一小段。資源一定放在某個子網路裡，並從那個子網路的範圍拿到私有 IP。

把資源分到不同子網路，主要是為了用不同的規則管理它們。最常見的分法是：

| 子網路 | 放什麼 | 能不能從網際網路直接連進來 |
|---|---|---|
| 公有子網路 | 負載平衡器、跳板機 | 可以（有公有 IP，而且路由通往網際網路） |
| 私有子網路 | 應用程式伺服器、資料庫 | 不行 |

一個典型的網站架構：使用者連到公有子網路的負載平衡器，負載平衡器再把請求轉給私有子網路裡的應用程式，應用程式連到同樣在私有子網路的資料庫。資料庫完全不需要被網際網路看到。

## 路由：決定封包往哪裡走

**路由**由「目的地」和「下一站」組成。每個網路都自動有一條本地路由，讓網路內的資源互相連通；要連到網際網路，則需要一條目的地是 `0.0.0.0/0`（所有位址）、下一站是網際網路閘道的路由，這叫做**預設路由**。

封包會套用**最符合的路由**：目的地是網路內的位址，就走本地路由；其他位址才走預設路由。

## 讓私有子網路也能上網：NAT

私有子網路的機器不能被外面連進來，但常常需要**主動**連出去，例如下載系統更新、呼叫外部 API。這時候用 **NAT**（網路位址轉譯）：

- 機器把連線送到 NAT，NAT 換成自己的公有 IP 再送出去。
- 回應依原路回來，送回原本的機器。
- 外面的人**無法主動**連到私有子網路裡的機器。

兩個平台都有受管理的 NAT 服務，會按時數和處理的流量收費。如果機器只是要存取同一個雲端的服務（例如物件儲存），兩個平台也都有不經過網際網路的私有連線方式，可以省下 NAT 的流量費用。

## 兩層防火牆

雲端網路的防火牆規則，最重要的觀念是**有狀態**和**無狀態**的差別：

| | 有狀態 | 無狀態 |
|---|---|---|
| 回應封包 | 允許了一個方向的連線，回應自動放行 | 回應也要有規則明確允許 |
| 設定難度 | 簡單，只要想「誰可以連進來」 | 要同時想進和出，包含回應使用的連接埠 |

AWS 的安全群組和 Google Cloud 的 VPC 防火牆規則都是**有狀態**的。AWS 另外還有子網路層級、**無狀態**的網路 ACL，可以當成第二道防線。

## 連接其他網路

網路之間也可以互相連接：

- **網路對等互連**（peering）：讓兩個 VPC 用私有 IP 互通。兩個平台的對等互連都**不可遞移**：A 連 B、B 連 C，不代表 A 能連到 C，要另外建立 A 和 C 的連線。
- **VPN**：透過網際網路上的加密通道，把雲端網路和公司機房接起來。
- **專線**：向供應商申請實體專線，頻寬和延遲比 VPN 穩定。AWS 叫 Direct Connect，Google Cloud 叫 Cloud Interconnect。

這些連線都要求兩邊的 IP 範圍**不重疊**，這就是一開始要好好規劃範圍的原因。

### Amazon VPC

在 AWS，一個 **VPC 屬於一個 Region**，可以使用這個 Region 所有的可用區；而**一個子網路只在一個可用區**。要讓服務撐過一個可用區故障，就要在兩個以上的可用區各建子網路。

**IP 範圍**：建立 VPC 時指定 IPv4 CIDR，大小介於 `/16`（65,536 個位址）到 `/28`（16 個位址）之間。子網路從 VPC 的範圍切出來，大小同樣介於 `/16` 到 `/28`，彼此不能重疊。

**保留位址**：每個子網路的前四個和最後一個位址不能使用。以 `10.0.0.0/24` 為例：

| 位址 | 用途 |
|---|---|
| 10.0.0.0 | 網路位址 |
| 10.0.0.1 | VPC 路由器 |
| 10.0.0.2 | DNS 伺服器 |
| 10.0.0.3 | 保留給未來使用 |
| 10.0.0.255 | 廣播位址（VPC 不支援廣播，所以保留） |

**預設 VPC**：每個 Region 都有一個預設 VPC，範圍是 `172.31.0.0/16`，每個可用區有一個 `/20` 的預設子網路，並已連接網際網路閘道。在預設子網路啟動的執行個體會自動拿到公有 IP，可以直接上網。適合快速試用，但正式環境通常會自己建立 VPC。

**網際網路閘道**（internet gateway）：要讓 VPC 連上網際網路，必須建立網際網路閘道、連接到 VPC，並在路由表加上指向它的路由。網際網路閘道本身不收費。

**路由表**：每個 VPC 有一個**主路由表**，沒有明確關聯其他路由表的子網路都使用它。也可以建立自訂路由表，再關聯到特定子網路。一個子網路同時只能關聯一個路由表。

**公有子網路的定義**：在 AWS，子網路是公有還是私有，**由它的路由表決定**：

- 路由表有一條通往網際網路閘道的路由，就是**公有子網路**。
- 沒有這條路由，就是**私有子網路**。

另外，自己建立的子網路預設**不會**自動分配公有 IP。公有子網路裡的執行個體要有公有 IP（或彈性 IP）才能和網際網路通訊，可以修改子網路的「自動指派公有 IPv4 位址」設定。

<Callout title="不要動主路由表">
如果把通往網際網路閘道的路由加在主路由表上，所有沒有明確關聯路由表的子網路都會變成公有子網路，包括你本來要當私有子網路的那些。比較安全的做法是保持主路由表只有本地路由，另外建立一個公有用的路由表，只關聯到公有子網路。
</Callout>

**NAT 閘道**：讓私有子網路的執行個體連出去。傳統的 NAT 閘道建在**公有子網路**裡、綁定一個彈性 IP，然後在私有子網路的路由表加上 `0.0.0.0/0` 指向 NAT 閘道的路由。這種 NAT 閘道只在一個可用區，那個可用區故障時，其他可用區用它上網的資源也會斷線，所以建議每個可用區各建一個。AWS 另外也推出了會自動跨可用區擴展的 Regional NAT 閘道。NAT 閘道按可用時數和處理的資料量收費。

**VPC 端點**：只是要存取 S3 或 DynamoDB 的話，可以建立**閘道端點**（gateway endpoint），流量不經過網際網路閘道或 NAT，而且不另外收費。

**安全群組和網路 ACL**

| | 安全群組 | 網路 ACL |
|---|---|---|
| 作用在 | 執行個體（網路介面） | 子網路 |
| 規則 | 只有允許規則 | 允許和拒絕規則都有 |
| 規則評估 | 評估所有規則後決定 | 依規則編號由小到大，符合第一條就套用 |
| 回應流量 | 自動允許（有狀態） | 必須明確允許（無狀態） |

預設的網路 ACL 允許所有進出流量，所以只用安全群組就能保護執行個體。網路 ACL 適合當成第二道防線，例如在子網路層級封鎖某段 IP。

**常用指令**

```bash
# 建立 VPC，記下輸出的 VpcId
aws ec2 create-vpc --cidr-block 10.0.0.0/16

# 在指定的可用區建立子網路
aws ec2 create-subnet --vpc-id vpc-0123456789abcdef0 --cidr-block 10.0.1.0/24 --availability-zone us-east-1a

# 建立網際網路閘道並連接到 VPC
aws ec2 create-internet-gateway
aws ec2 attach-internet-gateway --internet-gateway-id igw-0123456789abcdef0 --vpc-id vpc-0123456789abcdef0

# 建立路由表、加上預設路由、關聯到子網路
aws ec2 create-route-table --vpc-id vpc-0123456789abcdef0
aws ec2 create-route --route-table-id rtb-0123456789abcdef0 --destination-cidr-block 0.0.0.0/0 --gateway-id igw-0123456789abcdef0
aws ec2 associate-route-table --route-table-id rtb-0123456789abcdef0 --subnet-id subnet-0123456789abcdef0

# 讓這個子網路的執行個體自動拿到公有 IP
aws ec2 modify-subnet-attribute --subnet-id subnet-0123456789abcdef0 --map-public-ip-on-launch

# 查詢
aws ec2 describe-vpcs
aws ec2 describe-subnets --filters Name=vpc-id,Values=vpc-0123456789abcdef0
aws ec2 describe-route-tables --filters Name=vpc-id,Values=vpc-0123456789abcdef0
```

AWS 的網路資源都以產生的 **ID** 指定，每一步都要從上一步的輸出複製 ID。

</Provider>

### Google Cloud VPC

在 Google Cloud，**VPC 網路是全球資源**，不屬於任何區域；**子網路是區域資源**，一個子網路可以給該區域所有可用區的資源使用。所以同一個網路可以在台灣和美國各有一個子網路，兩邊的機器用私有 IP 直接互通，不需要額外的對等互連。

**IP 範圍**：網路本身沒有 IP 範圍，每個子網路各自指定。子網路最小是 `/29`（8 個位址）；Google 建議最大不要超過 `/8`。同一個網路裡的子網路範圍不能重疊。子網路建立後可以擴大，但不能縮小或替換。

**保留位址**：每個子網路主要範圍的前兩個和最後兩個位址不能使用。以 `10.1.2.0/24` 為例：網路位址 10.1.2.0、預設閘道 10.1.2.1、保留給未來使用的 10.1.2.254、廣播位址 10.1.2.255。

**auto 模式與自訂模式**

| | auto 模式 | 自訂模式（custom） |
|---|---|---|
| 子網路 | 每個區域自動建立一個，新區域上線也會自動加入 | 不會自動建立，完全由你決定 |
| IP 範圍 | 預先定義，都在 `10.128.0.0/9` 裡 | 自己指定 |
| 適合 | 快速試用 | 正式環境（Google 的建議） |

每個新專案都有一個 auto 模式的 **default 網路**。因為所有 auto 模式網路都用同一組範圍，兩個 auto 模式網路無法用對等互連或 VPN 接在一起。auto 模式可以單向轉換成自訂模式，不能轉回來。

**路由**：建立網路時，系統會自動建立一條目的地 `0.0.0.0/0`、下一站是**預設網際網路閘道**的預設路由，以及每個子網路的子網路路由。有外部 IP 的 VM 可以透過預設路由上網。

**防火牆規則**：設定在網路上，以網路標記或服務帳戶指定套用到哪些 VM。規則是**有狀態**的。

- 每條規則有**優先順序**，範圍 0 到 65535，預設 1000，數字越小越優先。
- 沒有任何規則符合時，套用**隱含規則**：拒絕所有輸入、允許所有輸出。
- default 網路預先建立了 `default-allow-internal`（允許來自 `10.128.0.0/9` 的流量）、`default-allow-ssh`、`default-allow-rdp`、`default-allow-icmp` 幾條規則，優先順序都是 65534。自己建立的網路則沒有這些規則，要自己加。

**Cloud NAT**：讓沒有外部 IP 的 VM 連到網際網路。Cloud NAT 設定在 **Cloud Router** 上，要建在 VM 所在子網路的**同一個區域**；它只處理回應封包，外面無法主動連進來。

**私人 Google 存取權**（Private Google Access）：在子網路上開啟後，只有內部 IP 的 VM 也能存取 Google 的 API 和服務，例如 Cloud Storage。

**共用 VPC**（Shared VPC）：機構可以把網路放在一個主專案，讓其他專案的資源使用它的子網路，由網路團隊集中管理。

**常用指令**

```bash
# 建立自訂模式的網路
gcloud compute networks create lab-net --subnet-mode=custom

# 在兩個區域各建立一個子網路
gcloud compute networks subnets create web-subnet --network=lab-net --region=asia-east1 --range=10.10.1.0/24
gcloud compute networks subnets create db-subnet --network=lab-net --region=us-central1 --range=10.20.1.0/24

# 防火牆規則要指定網路，否則會建在 default 網路
gcloud compute firewall-rules create lab-net-allow-ssh --network=lab-net --allow=tcp:22 --source-ranges=203.0.113.0/24

# 建立沒有外部 IP 的 VM，放在指定的子網路
gcloud compute instances create app-1 --zone=asia-east1-b --subnet=web-subnet --no-address

# 用 Cloud Router 加上 Cloud NAT，讓這個區域的 VM 可以連出去
gcloud compute routers create nat-router --network=lab-net --region=asia-east1
gcloud compute routers nats create nat-config --router=nat-router --region=asia-east1 --auto-allocate-nat-external-ips --nat-all-subnet-ip-ranges

# 查詢
gcloud compute networks list
gcloud compute networks subnets list --network=lab-net
```

Google Cloud 的網路資源都以**名稱**指定，子網路和 Cloud Router 還要加上區域。

## 兩個平台的差異

<Compare />

最大的差別在**範圍**：AWS 的 VPC 是區域性的、子網路綁在一個可用區；Google Cloud 的網路是全球的、子網路綁在一個區域。另外，「公有子網路」在 AWS 是由路由表決定的正式概念；在 Google Cloud，能不能上網主要看 VM 有沒有外部 IP，以及有沒有 Cloud NAT。

## 重點整理

- 虛擬網路是你在雲端上隔離出來的私有網路，大部分資源都放在裡面。
- IP 範圍要一開始就規劃好：留夠空間，而且不要和將來要連接的網路重疊。
- 每個子網路都有幾個保留位址：AWS 5 個，Google Cloud 4 個。
- 公有子網路放對外的入口，私有子網路放應用程式和資料庫；私有子網路要上網就用 NAT。
- 安全群組和 VPC 防火牆規則是有狀態的；AWS 的網路 ACL 是無狀態的。
- 網路對等互連不可遞移，而且兩邊的範圍不能重疊。
- AWS：VPC 屬於一個 Region、子網路在一個可用區，公有或私有由路由表決定。
- Google Cloud：網路是全球的、子網路是區域的；正式環境建議用自訂模式網路。
